# oq

Query, edit, and validate Org-mode documents with a reusable Rust core, CLI, and WebAssembly bindings.

[Documentation](docs/index.md) · [Agent quick reference](llms.txt) · [Full agent reference](llms-full.txt) ·
[API and schema contract](docs/contract.md) · [Contributing](docs/contributors/README.md)

`oq` exposes Org headings, property drawers, lists, checkboxes, description records,
and tables as JSON. jq expressions select data or update scalar values while
preserving every untargeted source byte. Declarative TOML schemas supply the
validation rules; the engine has no built-in application grammar.

```sh
oq query '.sections.Work.children[] | select(.properties.state == "active")' work.org
oq set -i '.sections.Work.children[0].properties.state = "done"' work.org
oq validate --schema checks.schema.toml work.org
```

## CLI reference

```text
oq — query, edit, and validate Org documents

Usage:
  oq query <jq-expression> <file.org>
  oq <jq-expression> <file.org>
  oq set [-i|--in-place] <jq-transformation> <file.org>
  oq validate --schema <schema.toml> <file.org>
  oq --help | oq -h
  oq --version

Options:
  -h, --help         Show this help; use as a standalone invocation.
  --version          Show the compiled version; use alone.
  -i, --in-place     For set only: update the input file atomically, with no stdout.
  --schema <path>    Required for validate: explicit TOML schema, with no default.

Output and defaults:
  query emits compact newline-separated JSON values, not an enclosing array.
  empty emits nothing; false and null emit JSON values. Each still exits 0.
  An array result is one JSON value; use .[] to emit its items.
  Without -i, set writes edited Org to stdout and leaves its input unchanged.
  validate writes one JSON report: {"mode":null,"diagnostics":[]} when valid.
  Each diagnostic has rule_id, severity (error/warning), line (1-based or null),
  and message. Warnings alone succeed; error diagnostics exit 1.
  Inputs and schemas are UTF-8 files. No command prompts for input.

Schemas:
  TOML requires version = 1. Add [[rules]] with id, assert (a jq predicate),
  and message; select defaults to ".", severity to "error", min_matches to 0.
  Use min_matches = 1 when an empty selection must fail. Assertions must emit
  exactly one boolean. Optional [[modes]] choose the first matching mode.

Environment:
  No oq-specific runtime environment variables or ambient configuration files.
  Files and schemas come only from explicit arguments; no schema autodiscovery.
  Build/install tools have their own environment; this describes the oq CLI.

Safety:
  set accepts supported scalar edits and new properties, not arbitrary tree edits.
  Invalid edits leave the input unchanged. In-place edits preserve permissions
  and require a writable regular file; symlinks are rejected.
  Expressions have no shell/process or external-module file loader. env, now,
  debug, stderr, and halt_error are unavailable; halt returns an error.
  Expressions can consume CPU/memory; this is not an untrusted-code sandbox.

Exit codes:
  0  Success, including empty/false/null query results and warning-only validation.
  1  Document validation has at least one error diagnostic (JSON on stdout).
  2  Usage, I/O, expression/edit, malformed schema, or schema-evaluation error.
    Error text is written to stderr.

Runnable schema examples and complete library reference: repository llms-full.txt.
```

## Validate a note

Run these blocks in order in an empty directory with `oq` on `PATH`.

<!-- oq:case:valid -->

```sh
cat > note.org <<'ORG'
* Note
:PROPERTIES:
:state: ready
:END:
ORG
cat > strict.toml <<'TOML'
version = 1
[[rules]]
id = "note.state"
select = ".children[]"
assert = '.properties.state == "ready"'
message = "State must be ready"
line = ".property_lines.state // .line"
min_matches = 1
TOML
oq validate --schema strict.toml note.org
```

Exit 0: JSON report with no diagnostics. The rule requires a note in state `ready`.

<!-- oq:case:rejected -->

```sh
oq set -i '.children[0].properties.state = "blocked"' note.org
oq validate --schema strict.toml note.org
```

Exit 1: JSON error `note.state` at line 3. The in-place edit itself is silent.

<!-- oq:case:warning -->

```sh
cp strict.toml warning.toml
printf '\nseverity = "warning"\n' >> warning.toml
oq validate --schema warning.toml note.org
```

Exit 0: the same violation is a warning diagnostic, not an error.

<!-- oq:case:malformed -->

```sh
printf 'version = [\n' > broken.toml
oq validate --schema broken.toml note.org
```

Exit 2: malformed schema; error text on stderr.

<!-- oq:case:usage -->

```sh
oq validate note.org
```

Exit 2: `--schema` is required even if a schema file exists nearby.

Install from source with a Rust toolchain:

```sh
cargo install --git https://github.com/agent-harbor/oq --branch dev --locked oq
```

For reproducible installs, replace `--branch dev` with `--rev <commit>`.
Nix users can build or run the same source revision:

```sh
nix run github:agent-harbor/oq/dev -- query '.title' work.org
```

The tag workflow produces native archives for Linux x64/arm64, macOS arm64, and
Windows x64/arm64, with SHA-256 checksums and detached signatures. Release npm
archives include compiled WASM and install without Rust. No JavaScript package
needs a native `oq` executable at runtime.

An immutable Git dependency instead fetches a source archive with prepared
JavaScript/declarations and the Rust inputs. With lifecycle scripts enabled,
dependency `postinstall` compiles its WASM after source fetching. Yarn checks its
locked archive checksum first; npm Git selects the pinned commit.
Provide Cargo/Rust and the `wasm32-unknown-unknown` standard library; the installer
does not install a compiler. Rebuild a valid prepared source installation with
`npm rebuild @agent-harbor/oq` or `yarn rebuild @agent-harbor/oq`. A Git fetch with
preparation disabled may lack the required inputs; rebuilding cannot supply
missing fetched files. Use a prebuilt release when build scripts are unavailable.
The [source package contract](docs/contributors/source-packages.md) explains
layouts and rebuild behavior.

In a contributor checkout, `npm ci`/`npm install` prepare source-package inputs.
Use `just build-bindings` or `npm run build` to build local WASM explicitly.
`just package` and `just release-package` create the separate prebuilt archive.

```js
import { readFile } from "node:fs/promises";
import { createOq } from "@agent-harbor/oq";
const wasm = await readFile(
  new URL(import.meta.resolve("@agent-harbor/oq/oq.wasm")),
);
const oq = await createOq(wasm);
console.log(oq.query("* Notes\n", ".children[].title")); // ['Notes']
```

The Rust API is available as `oq-core` in the same repository. Consumers can pin
its Git revision directly; no sibling checkout or workspace-relative dependency
is needed. See the [contract](docs/contract.md) for schema examples and supported
edit boundaries, and [AGENTS.md](AGENTS.md) for local verification commands.
